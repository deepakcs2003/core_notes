💉 Dependency Injection: Setter vs Constructor

📚 What is Dependency Injection?
Dependency Injection (DI) is a design pattern where Spring injects objects and values into your beans. There are two main ways: Setter Injection and Constructor Injection.

🧩 PART 1: Spring (XML) - Dependency Injection

1️⃣

Setter Injection (XML)

Spring uses the setter methods of a class to inject values or objects.

📁 Dev.java

package org.spring;

public class Dev {
    private int id;
    private String name;
    private Laptop laptop;

    public Dev() {
        System.out.println("Dev object created using default constructor");
    }

    // 🔹 Setter methods (used by Spring for Setter Injection)
    public void setId(int id) {
        this.id = id;
        System.out.println("Setter for id called");
    }

    public void setName(String name) {
        this.name = name;
        System.out.println("Setter for name called");
    }

    public void setLaptop(Laptop laptop) {
        this.laptop = laptop;
        System.out.println("Setter for laptop called");
    }

    public void build() {
        System.out.println(name + " (ID: " + id + ") is building a Spring app...");
        laptop.compile();
    }
}

📁 Laptop.java

package org.spring;

public class Laptop {
    private String brand;

    public Laptop() {
        System.out.println("Laptop object created using default constructor");
    }

    public void setBrand(String brand) {
        this.brand = brand;
        System.out.println("Setter for brand called");
    }

    public void compile() {
        System.out.println("Laptop from brand " + brand + " is compiling code...");
    }
}

📁 spring.xml

<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="
        http://www.springframework.org/schema/beans
        http://www.springframework.org/schema/beans/spring-beans.xsd">

    <!-- Define Laptop bean -->
    <bean id="laptop" class="org.spring.Laptop">
        <property name="brand" value="HP"/>
    </bean>

    <!-- Define Dev bean with setter injection -->
    <bean id="dev" class="org.spring.Dev">
        <property name="id" value="101"/>
        <property name="name" value="Deepak"/>
        <property name="laptop" ref="laptop"/>
    </bean>

</beans>

✅ Setter Injection = Using setX() methods in XML with <property>
2️⃣

Constructor Injection (XML)

Instead of calling setters, Spring can inject values through a constructor at the time of bean creation.

📁 Dev.java (constructor-based)

package org.spring;

public class Dev {
    private int id;
    private String name;
    private Laptop laptop;

    // 🔹 Constructor for injection
    public Dev(int id, String name, Laptop laptop) {
        System.out.println("Dev object created using constructor injection");
        this.id = id;
        this.name = name;
        this.laptop = laptop;
    }

    public void build() {
        System.out.println(name + " (ID: " + id + 
            ") is building using constructor injection...");
        laptop.compile();
    }
}

📁 spring.xml (constructor-arg instead of property)

<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="
        http://www.springframework.org/schema/beans
        http://www.springframework.org/schema/beans/spring-beans.xsd">

    <bean id="laptop" class="org.spring.Laptop">
        <property name="brand" value="Lenovo"/>
    </bean>

    <!-- Dev bean using constructor injection -->
    <bean id="dev" class="org.spring.Dev">
        <constructor-arg value="102"/>
        <constructor-arg value="Aman"/>
        <constructor-arg ref="laptop"/>
    </bean>
</beans>
✅ Output:
Laptop object created using default constructor
Setter for brand called
Dev object created using constructor injection
Aman (ID: 102) is building using constructor injection...
Laptop from brand Lenovo is compiling code...


                    

                        🧠 What's Happening?
                        
    
                            
  1. Spring sees <constructor-arg> → realizes it must use the matching constructor
    2. 
                            
  2. It matches arguments by order or type (you can also use index or name)
    3. 
                            
  3. Spring directly calls: new Dev(102, "Aman", laptopObject);
    4. 
                            
  4. No setters are called
    5. 
                        

                        
✅ Constructor Injection = Inject dependencies via constructor parameters

🧾 Setter vs Constructor Injection (Spring XML)

Feature Setter Injection Constructor Injection
Method used setX() Constructor
When called After object creation During object creation
XML Tag <property> <constructor-arg>
Flexibility More flexible, optional dependencies Best for required dependencies
Recommended when You have optional fields You have mandatory fields

Spring Configuration with Autowiring

📁 spring.xml

<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="
           http://www.springframework.org/schema/beans
           http://www.springframework.org/schema/beans/spring-beans.xsd">

    <!-- ✅ Dev bean with autowire byName -->
    <!-- It will look for a bean whose id matches the property name 'computer' -->
    <bean id="dev" class="org.spring.Dev" autowire="byName"/>

    <!-- ✅ Two possible computer beans -->
    <bean id="computer" class="org.spring.Laptop" primary="true"/>
    <bean id="desktop1" class="org.spring.Desktop"/>

</beans>
🔍 Step-by-step behavior of autowire="byName":
  1. Spring creates the Dev bean
  2. It checks for any property inside Dev — here we have setComputer(Computer computer)
  3. The property name is computer
  4. Spring looks for a bean in XML with id="computer"
  5. It finds <bean id="computer" class="org.spring.Laptop" .../>
  6. So, Laptop bean is injected into Dev
  7. When you call dev.build(), output will show Laptop's compile

Understanding

💡 Autowiring Concepts Explained

Concept Meaning Example
autowire="byName" Injects a bean whose id matches the property name <bean id="dev" autowire="byName"/>
autowire="byType" Injects bean by type (class/interface) if only one exists <bean id="dev" autowire="byType"/>
primary="true" If multiple beans of same type exist, the primary one is injected <bean id="computer" primary="true"/>
ref attribute Manual injection <property name="computer" ref="desktop1"/>
Variations

🧩 Try These Different Configurations

1️⃣ Using autowire="byType"

<bean id="dev" class="org.spring.Dev" autowire="byType"/>
➡️ Spring will inject Laptop because it's primary="true"

2️⃣ Manual Injection (no autowire)

<bean id="dev" class="org.spring.Dev">
    <property name="computer" ref="desktop1"/>
</bean>
➡️ This directly injects Desktop instead of Laptop

3️⃣ Multiple Beans without Primary

<bean id="laptop1" class="org.spring.Laptop"/>
<bean id="desktop1" class="org.spring.Desktop"/>
<bean id="dev" class="org.spring.Dev" autowire="byType"/>
⚠️ This will throw an error: NoUniqueBeanDefinitionException
Spring doesn't know which Computer implementation to inject!

🧠 Complete Autowiring Summary

Injection Type XML/Annotation How It Works
By Name <bean autowire="byName"/> Matches property name with bean id
By Type <bean autowire="byType"/> Matches property type with bean class
Manual ref <property name="computer" ref="desktop1"/> You decide explicitly
Primary primary="true" Used when multiple beans of same type exist
@Autowired Annotation Does autowiring automatically
@Qualifier Annotation Used with @Autowired to specify bean

✅ Decision Table: Which Bean Gets Injected?

Scenario Injected Bean Why
autowire="byName" and bean id = "computer" Laptop Matches name computer
autowire="byType" with primary laptop Laptop Because laptop is primary="true"
Manual ref to desktop1 Desktop Explicitly referenced
Remove primary, no ref, two same types ❌ Error Ambiguous dependency

📊 Autowiring Flow Diagram

How Spring resolves autowiring: byName, byType, and Primary beans

🎓 Key Takeaways

  • byName Matches the property name with bean ID
  • byType Matches the property type with bean class
  • Primary Resolves conflicts when multiple beans of same type exist
  • Ambiguity Without primary or qualifier, multiple beans cause errors
  • Manual Using ref attribute gives you explicit control
