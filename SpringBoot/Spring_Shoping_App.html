🚀 Spring Boot Shopping App Tutorial 🚀

Welcome, beginner! Let's build a simple shopping app backend with Spring Boot. This tutorial guides you to create a system where users can sign up, log in, browse products, manage a cart, and place orders. Admins can add or remove products. We'll keep it clear and fun!

For each step, we'll:

  • Explain what and why.
  • Provide clean, short code.
  • Break down the code line by line with logic and working.
  • Show how to add it to your project.
Note: We're skipping complex features like payments or JWT to focus on core Spring Boot concepts: APIs, databases, and security. Want more? Ask!

Prerequisites:

  • Java (version 17+).
  • IDE like IntelliJ Community or Eclipse (free).
  • MySQL (free community edition) running.
  • Postman to test APIs.

Ready? Let's dive in! 🎉

Step 2: Configure MySQL Database

Why? MySQL stores data like users and products. Spring Data JPA maps Java objects to database tables.

Steps:

  1. Open MySQL (command line or MySQL Workbench).
  2. Create database:
SQL

CREATE DATABASE shopping_app;

Code Explanation & Logic:

  • CREATE DATABASE: Creates a MySQL database named shopping_app.
  • Logic: This sets up an empty database for storing tables created by Spring Boot.
  • Working: MySQL allocates space for the database, ready for tables to be defined by our Java entities.
  1. Add config to src/main/resources/application.properties:
application.properties

spring.datasource.url=jdbc:mysql://localhost:3306/shopping_app?useSSL=false&serverTimezone=UTC
spring.datasource.username=root  # Your MySQL username
spring.datasource.password=your_password  # Your MySQL password

spring.jpa.hibernate.ddl-auto=update  # Auto-creates tables
spring.jpa.show-sql=true  # Shows SQL for learning
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.MySQL8Dialect

Code Explanation & Logic:

  • spring.datasource.url: Connects to MySQL at localhost:3306/shopping_app.
  • username/password: Authenticates with MySQL.
  • ddl-auto=update: Hibernate creates/updates tables based on Java entities.
  • show-sql=true: Logs SQL queries for debugging.
  • dialect: Ensures MySQL-compatible SQL.
  • Logic: Configures Spring to connect to MySQL and manage tables automatically.
  • Working: On app start, Spring uses these settings to establish a connection and prepare the database.
Test It: Restart app. No errors? Database is connected! 🎉

Step 3: Plan Data Models (Entities)

Why? Entities define database tables as Java classes. Our app needs:

  • User: Stores customers or admins.
  • Role: Defines "USER" or "ADMIN".
  • Product: Items for sale.
  • Cart: User’s shopping basket.
  • Order: Placed purchases.

Relationships:

  • User ↔ Roles: Many-to-many (users can have multiple roles).
  • Cart ↔ User: One-to-one (each user has one cart).
  • Cart ↔ Products: Many-to-many (cart holds multiple products).
  • Order ↔ User: Many-to-one (user can have multiple orders).
  • Order ↔ Products: Many-to-many (order includes multiple products).

Logic & Working: Entities map to database tables via JPA annotations. Relationships ensure data is linked correctly (e.g., a cart belongs to one user).

4.2: User.java

User.java

import jakarta.persistence.*;
import lombok.Data;
import java.util.HashSet;
import java.util.Set;

@Entity
@Data
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String email;
    private String password;

    @ManyToMany(fetch = FetchType.EAGER)
    @JoinTable(name = "user_roles",
               joinColumns = @JoinColumn(name = "user_id"),
               inverseJoinColumns = @JoinColumn(name = "role_id"))
    private Set<Role> roles = new HashSet<>();
}

Code Explanation & Logic:

  • @Table(name="users"): Names table users.
  • @ManyToMany: Links users to multiple roles.
  • @JoinTable: Creates user_roles table for relationships.
  • fetch = FetchType.EAGER: Loads roles when user is fetched.
  • Logic: Stores user data and their roles for authentication/authorization.
  • Working: Hibernate creates users and user_roles tables, linking users to roles.

RoleService.java

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class RoleService {
    @Autowired
    private RoleRepository roleRepository;

    public void initRoles() {
        if (roleRepository.findByName("USER") == null) {
            Role userRole = new Role();
            userRole.setName("USER");
            roleRepository.save(userRole);
        }
        if (roleRepository.findByName("ADMIN") == null) {
            Role adminRole = new Role();
            adminRole.setName("ADMIN");
            roleRepository.save(adminRole);
        }
    }
}

Code Explanation & Logic:

  • @Service: Marks as a service bean.
  • @Autowired: Injects RoleRepository.
  • initRoles: Creates default roles if they don’t exist.
  • Logic: Ensures "USER" and "ADMIN" roles are in DB for security.
  • Working: Checks DB, creates roles if missing, and saves them.

6.2: UserService.java

UserService.java

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.stereotype.Service;
import java.util.Optional;

@Service
public class UserService {

    @Autowired
    private UserRepository userRepository;

    @Autowired
    private RoleRepository roleRepository;

    @Autowired
    private BCryptPasswordEncoder passwordEncoder;

    // Register a new user
    public User registerUser(String name, String email, String password, String roleName) {
        User user = new User();
        user.setName(name);
        user.setEmail(email);
        user.setPassword(passwordEncoder.encode(password)); // Encrypt password

        Role role = roleRepository.findByName(roleName); // Fetch role from DB
        user.getRoles().add(role); // Assign role to user

        return userRepository.save(user); // Save user in DB
    }

    // Find user by email (used for login)
    public Optional<User> findByEmail(String email) {
        return userRepository.findByEmail(email);
    }
}

Code Explanation & Logic:

  • @Service: Marks this as a service layer in Spring Boot where business logic is written.
  • @Autowired: Lets Spring automatically inject the required dependencies.
  • BCryptPasswordEncoder: Encrypts (hashes) the password before saving it to the database for security.
  • registerUser(): Creates a new user, encrypts their password, assigns a role, and saves the user in the database.
  • findByEmail(): Looks up a user by email and returns it inside an Optional to safely handle null values.
  • Logic: Handles user registration and secure password management, ensuring each user gets a role and encrypted credentials.
  • What is Optional?:
    • Optional<User> is a wrapper object that may or may not contain a user value.
    • It helps avoid NullPointerException by forcing you to check if data exists before using it.
    • Example: 
      
Optional<User> userOpt = userService.findByEmail("abc@gmail.com");
if (userOpt.isPresent()) {
    User user = userOpt.get(); // Safe access
} else {
    // User not found
}
  • Working:
    • User details are received from frontend.
    • Password is encrypted with BCryptPasswordEncoder.
    • Role is fetched and assigned.
    • User is saved securely into the database.

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class CartService {
    @Autowired
    private CartRepository cartRepository;
    @Autowired
    private ProductService productService;

    public Cart addToCart(Long userId, Long productId) {
        Cart cart = cartRepository.findByUserId(userId);
        if (cart == null) {
            cart = new Cart();
        }
        Product product = productService.getProductById(productId).orElseThrow();
        cart.getProducts().add(product);
        return cartRepository.save(cart);
    }

    public Cart getCart(Long userId) {
        return cartRepository.findByUserId(userId);
    }
}

Code Explanation & Logic:

  • Working: Updates cart_products table with product associations.

6.5: OrderService.java

OrderService.java

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import java.time.LocalDateTime;
import java.util.List;

@Service
public class OrderService {
    @Autowired
    private OrderRepository orderRepository;
    @Autowired
    private CartService cartService;
    @Autowired
    private ProductService productService;

    public Order placeOrder(Long userId) {
        Cart cart = cartService.getCart(userId);
        if (cart == null || cart.getProducts().isEmpty()) {
            throw new RuntimeException("Cart is empty");
        }

        Order order = new Order();
        order.setUser(cart.getUser());
        order.setProducts(new ArrayList<>(cart.getProducts()));
        order.setOrderDate(LocalDateTime.now());
        order.setStatus("PLACED");

        for (Product p : cart.getProducts()) {
            p.setStock(p.getStock() - 1);
            productService.addProduct(p);
        }

        cart.getProducts().clear();
        cartService.addToCart(userId, null);

        return orderRepository.save(order);
    }

    public List<Order> getUserOrders(Long userId) {
        return orderRepository.findByUserId(userId);
    }
}

Code Explanation & Logic:

  • placeOrder: Converts cart to order, reduces stock, clears cart.
  • getUserOrders: Retrieves order history.
  • Logic: Ensures cart isn’t empty, updates stock, and saves order.
  • Working: Copies cart products to order, updates DB, and clears cart.

Step 7: Spring Security Setup

Why? Spring Security is used to protect your REST APIs by verifying user identity and restricting access based on roles (like ADMIN or USER).

Create src/main/java/com/example/shoppingapp/config/SecurityConfig.java.

SecurityConfig.java

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.authentication.builders.AuthenticationManagerBuilder;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.core.userdetails.UsernameNotFoundException;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.core.authority.SimpleGrantedAuthority;
import java.util.stream.Collectors;

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Autowired
    private UserService userService;

    @Bean
    public BCryptPasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(); // Encrypts passwords
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf().disable() // Disable CSRF for REST APIs
            .authorizeHttpRequests() // Define URL access rules
                .requestMatchers("/api/auth/**").permitAll() // Open endpoints
                .requestMatchers("/api/admin/**").hasRole("ADMIN") // Only ADMIN can access
                .requestMatchers("/api/user/**").hasRole("USER") // Only USER can access
                .anyRequest().authenticated() // All other routes require login
            .and()
            .httpBasic(); // Enable HTTP Basic authentication

        return http.build();
    }

    @Autowired
    public void configureGlobal(AuthenticationManagerBuilder auth) throws Exception {
        auth.userDetailsService(new UserDetailsService() {
            @Override
            public UserDetails loadUserByUsername(String email) throws UsernameNotFoundException {
                User user = userService.findByEmail(email)
                    .orElseThrow(() -> new UsernameNotFoundException("User not found"));
                
                return new org.springframework.security.core.userdetails.User(
                    user.getEmail(),
                    user.getPassword(),
                    user.getRoles()
                        .stream()
                        .map(role -> new SimpleGrantedAuthority("ROLE_" + role.getName()))
                        .collect(Collectors.toList())
                );
            }
        }).passwordEncoder(passwordEncoder());
    }
}

Code Explanation & Logic:

  • @EnableWebSecurity: Enables Spring Security for the entire project.
  • passwordEncoder(): Creates a BCryptPasswordEncoder bean to encrypt user passwords before storing them.
  • securityFilterChain(): Defines security rules for HTTP requests.
    • /api/auth/** → Open for everyone (e.g., signup, login).
    • /api/admin/** → Accessible only to users with ADMIN role.
    • /api/user/** → Accessible only to users with USER role.
    • All other URLs → Require authentication.
  • configureGlobal(): Sets up how Spring should load user details from your database for authentication.
    • Uses UserService.findByEmail() to find the user from DB.
    • The Optional returned from findByEmail ensures null safety — if no user exists, it throws UsernameNotFoundException.
    • Maps each role to SimpleGrantedAuthority("ROLE_" + roleName) to tell Spring Security which roles the user has.
  • Logic:
    • Every incoming request passes through Spring Security.
    • It checks if the user is authenticated and authorized (has correct role).
    • If valid → request proceeds. If not → access denied.
  • Working:
    • User logs in using email and password.
    • Password is verified using BCryptPasswordEncoder.
    • Roles are checked (ADMIN/USER) before allowing access to APIs.
  • What is Optional and Why Used?
    • Optional<User> is a container object introduced in Java 8 to handle values that might be null.
    • In findByEmail(), if a user is not found, it prevents NullPointerException and allows you to handle it gracefully using orElseThrow().
    • Example: 
      
Optional<User> userOpt = userService.findByEmail("abc@gmail.com");
User user = userOpt.orElseThrow(() -> new UsernameNotFoundException("User not found"));
