Validation (@Valid, @NotNull, @Size)

What is it?

Validation ensures that data coming into your application (e.g., from user input) meets certain rules. This prevents errors like saving empty names or invalid emails. Spring Boot uses the Jakarta Bean Validation API (part of Hibernate Validator) for this.

Key Annotations:

  • @Valid: Placed on a method parameter (e.g., in a controller) to trigger validation on an object.
  • @NotNull: Ensures a field cannot be null (empty).
  • @Size: Checks the length of a string or collection (e.g., min and max size).
Why use it? It catches bad data early, improves security, and provides user-friendly error messages.

Example Implementation:

Step 1: Add dependency in pom.xml (Maven):

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>

Step 2: Create User class (DTO - Data Transfer Object):

import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Size;

public class User {
    @NotNull(message = "Name cannot be null")
    @Size(min = 2, max = 50, message = "Name must be between 2 and 50 characters")
    private String name;

    @NotNull(message = "Email cannot be null")
    @Size(min = 5, message = "Email must be at least 5 characters")
    private String email;

    // Getters and setters
}

Step 3: Use in Controller:

import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;
import jakarta.validation.Valid;

@RestController
public class UserController {
    @PostMapping("/users")
    public String createUser(@Valid @RequestBody User user) {
        return "User created successfully!";
    }
}
💡 Tips:
  • Validation happens automatically with @Valid
  • Use other annotations like @Email for email format or @Min for numbers
  • If validation fails, Spring throws MethodArgumentNotValidException

Exception Handling (@ControllerAdvice, @ExceptionHandler)

What is it?

Exceptions are errors that occur during runtime (e.g., invalid input or database issues). Spring Boot lets you handle them globally instead of in every method.

Key Annotations:

  • @ControllerAdvice: A class that handles exceptions across all controllers.
  • @ExceptionHandler: A method in @ControllerAdvice that catches a specific exception and returns a response.
Why use it? It keeps your code clean and provides consistent error responses (e.g., JSON with error details) instead of ugly stack traces.

Example: Global Exception Handler

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;

@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<String> handleValidationExceptions(
            MethodArgumentNotValidException ex) {
        String errorMessage = ex.getBindingResult()
                                .getFieldErrors()
                                .get(0)
                                .getDefaultMessage();
        return new ResponseEntity<>("Error: " + errorMessage, 
                                     HttpStatus.BAD_REQUEST);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<String> handleGeneralExceptions(Exception ex) {
        return new ResponseEntity<>("An error occurred: " + ex.getMessage(), 
                                     HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
💡 Tips:
  • Use specific handlers for different exceptions (e.g., NoSuchElementException for "not found")
  • This is global, so no need to repeat try-catch in every method
  • Returns custom error messages instead of default Spring error pages

Configuration (application.properties / application.yml)

What is it?

These are files where you configure your app's settings, like database URL, server port, or custom properties. Spring Boot loads them automatically.

  • application.properties: Key-value format
  • application.yml: YAML format (more readable with indentation)
Why use it? It separates config from code, making it easy to change settings without rebuilding the app (e.g., switch databases).

Example: application.properties

server.port=8081
spring.datasource.url=jdbc:mysql://localhost:3306/mydb
my.custom.property=Hello World

Example: application.yml (equivalent)

server:
  port: 8081
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/mydb
my:
  custom:
    property: Hello World

Accessing in Code:

import org.springframework.beans.factory.annotation.Value;

@Value("${my.custom.property}")
private String customProp;  // Injects "Hello World"
💡 Tips:
  • YAML is preferred for nested configs
  • Override with environment variables for production
  • Use different files for different environments

Profiles (@Profile)

What is it?

Profiles let you run different configs for environments like "dev" (development), "prod" (production), or "test". Use @Profile on classes or methods to activate them only in specific profiles.

Why use it? Apps behave differently in dev (e.g., fake data) vs. prod (real database).

Example Implementation:

Step 1: Create profile-specific configs:

  • application-dev.properties: For development environment
  • application-prod.properties: For production environment
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Profile;

@Configuration
public class AppConfig {

    @Bean
    @Profile("dev")
    public DataSource devDataSource() {
        // Return in-memory DB for development
    }

    @Bean
    @Profile("prod")
    public DataSource prodDataSource() {
        // Return real DB for production
    }
}

How to Activate:

// In application.properties
spring.profiles.active=dev

// Or run with command line
--spring.profiles.active=dev
💡 Tips: Great for testing without affecting production data and configurations.

Swagger/OpenAPI for API Documentation

What is it?

Swagger (now OpenAPI) auto-generates interactive docs for your REST APIs. Users can browse endpoints, try requests, and see responses.

Why use it? Makes APIs self-documenting, easier for teams or clients to use.

Example Setup:

Step 1: Add dependency:

<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.0.2</version>
</dependency>

Step 2: Access docs at:

http://localhost:8080/swagger-ui.html

Step 3: Customize in application.properties:

springdoc.swagger-ui.path=/api-docs
💡 Tips:
  • Annotate controllers with @Operation for better descriptions
  • Use @Schema on models for field descriptions
  • It scans your @RestController classes automatically

Spring Boot DevTools (Hot Reload)

What is it?

DevTools is a module for faster development. It enables "hot reload" – automatically restarts the app when you change code, without manual rebuilds.

Why use it? Saves time during coding; changes appear instantly.

Example Setup:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-devtools</artifactId>
    <scope>runtime</scope>
</dependency>
How it works:
  • Run your app via IDE
  • Edit a class or template
  • App restarts automatically in seconds
  • Also caches less for quick refreshes
💡 Tips:
  • Disable in production (dev-only)
  • Works best with IDEs like IntelliJ or Eclipse

Assume you have a basic CRUD project for "Books" (e.g., a Book entity, repository, service, controller).

public class Book {

    @Size(min = 1, max = 100, message = "Title must be between 1 and 100 characters")
    private String title;

    @NotNull(message = "Author cannot be null")
    private String author;
    
    // Getters and setters
}

In Controller (for create operation):

@PostMapping("/books")
public Book createBook(@Valid @RequestBody Book book) {
    return bookService.save(book);
}

Step 2: Add Exception Handling

Create GlobalExceptionHandler with a handler for NoSuchElementException:

@ExceptionHandler(NoSuchElementException.class)
public ResponseEntity<String> handleNotFound(NoSuchElementException ex) {
    return new ResponseEntity<>("Resource not found", HttpStatus.NOT_FOUND);
}

In service, throw exceptions when a book isn't found:

throw new NoSuchElementException();

Step 3: Test It

  1. Run the application
  2. Use Postman to send invalid data (e.g., empty title) → should get "Error: Title cannot be null"
  3. Try getting a non-existent book → should get "Resource not found"
