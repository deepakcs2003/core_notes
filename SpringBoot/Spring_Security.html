Comprehensive Guide to Spring Security in Spring Boot - Notes

Introduction to Spring Security in Spring Boot

Spring Security is a powerful framework within the Spring ecosystem that provides comprehensive security services for Java-based applications, particularly web applications built with Spring Boot. It handles authentication (who you are), authorization (what you can do), and protection against common vulnerabilities like CSRF, XSS, and session fixation. Spring Security integrates seamlessly with Spring Boot, making it easy to secure REST APIs, web pages, and more.

Key Principles

  • Filters: Spring Security uses a chain of filters to intercept requests and apply security rules.
  • Authentication and Authorization: Supports multiple providers (e.g., database, LDAP, OAuth2).
  • Default Behavior: Adding the dependency enables basic security (e.g., login form with generated credentials).
  • Customization: Override defaults via configuration classes.
  • OWASP Compliance: Aligns with OWASP Top 10 security risks (e.g., injection, broken authentication).

We'll cover all the listed topics step-by-step, with explanations, examples, and code snippets. Assume a basic Spring Boot setup (Maven/Gradle, Java 17+). Code examples are in Java.

1. Spring Security Getting Started

Concept

- Spring Security protects resources (e.g., endpoints) by requiring authentication.

- By default, it provides a login form, session management, and a generated password.

- It uses a filter chain (e.g., UsernamePasswordAuthenticationFilter) to intercept requests before they reach controllers.

- Behind the scenes: Requests pass through a dispatcher servlet, then security filters, before hitting your code.

Example Setup

  1. Add dependency in pom.xml:
    2. 
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
  2. Create a simple controller:
    3. 
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {
    @GetMapping("/homepage")
    public String greet() {
        return "Welcome to Telescope!";
    }
}
  3. Run the app (http://localhost:8080/homepage). You'll see a login form.
    • Default username: user
    • Password: Printed in console (e.g., "Using generated security password: abc123...").

Explanation

- Adding the dependency auto-configures security.

- Filters like SecurityContextPersistenceFilter and UsernamePasswordAuthenticationFilter handle login and sessions.

- Sessions use cookies (e.g., JSESSIONID) to maintain state.

Important Addition: Why Start Here?

- Understand the filter chain: Requests go through DispatcherServlet → Security Filters → Controller.

- Key Filters: BasicAuthenticationFilter, DefaultLoginPageGeneratingFilter.

2. Setting Our Own Username and Password

Concept

- Default credentials are for development only.

- Override in application.properties for a single user (not recommended for production; use database instead).

- For multiple users, use in-memory configuration or database.

Example

In application.properties:


spring.security.user.name=navin
spring.security.user.password=telescope

Controller remains the same. Now login with navin / telescope.

Code Explanation

- Spring Security's InMemoryUserDetailsManager uses these properties.

- For in-memory multiple users (in SecurityConfig.java):


import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.provisioning.InMemoryUserDetailsManager;

@Configuration
@EnableWebSecurity
public class SecurityConfig {
    @Bean
    public UserDetailsService userDetailsService() {
        return new InMemoryUserDetailsManager(
            User.withDefaultPasswordEncoder().username("navin").password("telescope").roles("USER").build(),
            User.withDefaultPasswordEncoder().username("admin").password("admin123").roles("ADMIN").build()
        );
    }
}

- Explanation: InMemoryUserDetailsManager implements UserDetailsService to load users. User.withDefaultPasswordEncoder() creates users with plain-text passwords (use BCrypt in production).

Important Addition: In-Memory with Roles

- Introduce roles early for authorization preview.

- Example: Add .roles("ADMIN") in in-memory users.

3. CSRF Token

Concept

- CSRF (Cross-Site Request Forgery): An attack where a malicious site tricks a user into performing actions on your site (e.g., via forged requests).

- Spring Security enables CSRF protection by default for POST/PUT/DELETE (state-changing) requests.

- It generates a token stored in session; clients must include it in requests.

- For GET requests, CSRF is usually disabled (read-only).

- Disable for stateless APIs (e.g., with JWT), but use other protections.

Example

- Enable CSRF (default). In a controller:


@PostMapping("/students")
public Student addStudent(@RequestBody Student student) {
    // Add logic
    return student;
}

- To POST via Postman: First GET a CSRF token (e.g., from /csrf-token endpoint), then add header X-CSRF-TOKEN: <token>.

Custom endpoint for CSRF token:


@GetMapping("/csrf-token")
public CsrfToken getCsrfToken(HttpServletRequest request) {
    return (CsrfToken) request.getAttribute("_csrf");
}

- Disable CSRF (in SecurityConfig.java):


@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    return http
        .csrf(csrf -> csrf.disable())  // Lambda style
        .authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
        .formLogin(Customizer.withDefaults())
        .httpBasic(Customizer.withDefaults())
        .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .build();
}

Explanation

- CSRF filter (CsrfFilter) checks for _csrf token in requests.

- For REST clients (Postman), fetch token first or disable for stateless apps.

- Making sessions stateless (as above) avoids CSRF need, but use JWT for auth.

Important Addition: CSRF in Forms

- For Thymeleaf/HTML forms: Use <input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}"/>.

- Why Important: Prevents forged requests; always enable unless stateless (e.g., JWT APIs).

4. Spring Security Configuration

Concept

- Use @Configuration and @EnableWebSecurity to override defaults.

- SecurityFilterChain bean defines the filter chain.

- Customize: Disable CSRF, enable form/HTTP Basic login, session management, etc.

- Builder pattern for readability.

Example (SecurityConfig.java)


@Configuration
@EnableWebSecurity
public class SecurityConfig {
    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/login", "/register").permitAll()
                .anyRequest().authenticated())
            .formLogin(Customizer.withDefaults())
            .httpBasic(Customizer.withDefaults())
            .build();
    }
}

Explanation

- HttpSecurity configures filters.

- authorizeHttpRequests: Permits public endpoints, authenticates others.

- formLogin: Enables default login form.

- httpBasic: For REST clients (Postman).

- Imperative style (non-lambda): Use http.csrf().disable() etc.

Additional Customizations

- Logout Configuration:


http.logout(logout -> logout
    .logoutUrl("/logout")
    .logoutSuccessUrl("/login?logout")
    .invalidateHttpSession(true)
    .deleteCookies("JSESSIONID"));

- Explanation: Custom logout URL, redirects after logout, clears session/cookies.

- Remember-Me:


http.rememberMe(remember -> remember
    .key("uniqueAndSecret")  // Secure key
    .tokenValiditySeconds(86400));  // 1 day

- Explanation: Persistent login via cookie. Add <input type="checkbox" name="remember-me"/> in form.

- HTTPS Enforcement:


http.requiresChannel(channel -> channel
    .anyRequest().requiresSecure());  // Force HTTPS

- Explanation: Redirects HTTP to HTTPS. Configure SSL in application.properties (e.g., keystore).

- CORS for APIs:


http.cors(cors -> cors.configurationSource(request -> {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOrigins(List.of("http://localhost:3000"));
    config.setAllowedMethods(List.of("GET", "POST"));
    return config;
}));

- Explanation: Allows cross-origin requests (e.g., from React frontend).

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.core.userdetails.UsernameNotFoundException;
import org.springframework.stereotype.Service;

@Service
public class MyUserDetailsService implements UserDetailsService {
    @Autowired
    private UserRepo repo;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        Users user = repo.findByUsername(username);
        if (user == null) {
            throw new UsernameNotFoundException("User not found");

        return new UserPrincipal(user);  // Custom UserDetails impl
    }
}
  6. Custom UserDetails (UserPrincipal.java):

import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.userdetails.UserDetails;
import java.util.Collection;
import java.util.Collections;

public class UserPrincipal implements UserDetails {
    private Users user;

    public UserPrincipal(Users user) {
        this.user = user;
    }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return Collections.singleton(() -> "USER");  // Simple role
    }

    @Override
    public String getPassword() {
        return user.getPassword();
    }

    @Override
    public String getUsername() {
        return user.getUsername();
    }

    @Override
    public boolean isAccountNonExpired() { return true; }
    @Override
    public boolean isAccountNonLocked() { return true; }
    @Override
    public boolean isCredentialsNonExpired() { return true; }
    @Override
    public boolean isEnabled() { return true; }
}

6. Spring Security Bcrypt Password Encoder

Concept

- Store passwords as hashes (one-way) to prevent breaches.

- BCrypt: Salts and hashes passwords with multiple rounds (e.g., 12) for security.

- Use for registration (hash before save) and login (hash input and compare).

Example

  1. In SecurityConfig:
    2. 
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(12);  // 12 rounds
}
  2. Update provider:
    3. 
provider.setPasswordEncoder(passwordEncoder());
  3. In User Service (for registration):
    4. 
@Service
public class UserService {
    @Autowired
    private UserRepo repo;
    @Autowired
    private PasswordEncoder encoder;

    public Users register(Users user) {
        user.setPassword(encoder.encode(user.getPassword()));
        return repo.save(user);
    }
}

Explanation

- encode: Hashes plain text.

- During login, Spring compares hashed input with stored hash.

- Avoid plain text or weak encoders (e.g., NoOp).

Important Addition: Password Policies

- Enforce strong passwords in registration (e.g., regex validation).

- Rotate keys periodically for BCrypt.

7. What is JWT and Why

Concept

- JWT (JSON Web Token): Compact, self-contained token for secure info exchange.

- Structure: Header (algorithm), Payload (claims like username, exp), Signature.

- Why: Stateless auth (no sessions), scalable for microservices, avoids DB lookups per request.

- Use cases: APIs, single sign-on.

Explanation

- Signed with secret key (HMAC) or public/private keys (RSA).

- Claims: iss (issuer), sub (subject), exp (expiration), iat (issued at).

- Why over sessions: No server-side storage, portable across services.

Expanded: JWT vs Sessions – JWT is stateless, scalable; sessions stateful, server-dependent.

9. Generating JWT Token

Concept

- On successful login, generate token with claims, sign it.

- Use JwtBuilder to build.

Example (in JwtService.java)


import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import org.springframework.stereotype.Service;

import javax.crypto.SecretKey;
import java.util.Date;
import java.util.HashMap;
import java.util.Map;

@Service
public class JwtService {
    private SecretKey getKey() {
        // Generate secure key (use secure random in prod)
        return Keys.hmacShaKeyFor("your-secure-key-here".getBytes());
    }

    public String generateToken(String username) {
        Map<String, Object> claims = new HashMap<>();
        return Jwts.builder()
            .claims(claims)
            .subject(username)
            .issuedAt(new Date(System.currentTimeMillis()))
            .expiration(new Date(System.currentTimeMillis() + 1000 * 60 * 30))  // 30 min
            .signWith(getKey())
            .compact();
    }
}

In Login Controller:


@PostMapping("/login")
public String login(@RequestBody Users user) {
    // Authenticate user...
    if (authenticated) {
        return jwtService.generateToken(user.getUsername());
    }
    return "Failure";
}

Explanation

- Build token with subject (username), iat, exp.

- Sign with HMAC key.

Addition: Refresh Tokens

- Generate refresh token (long-lived) alongside access token (short-lived).

- Example: In JwtService, add generateRefreshToken() with longer exp.

- Validate and issue new access token on refresh request.

10. Validating Token

Concept

- Extract token from "Authorization: Bearer <token>".

- Verify signature, claims, expiration.

- Use custom filter before username/password filter.

Example Filter (JwtFilter.java extends OncePerRequestFilter)


import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.web.authentication.WebAuthenticationDetailsSource;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;

@Component
public class JwtFilter extends OncePerRequestFilter {
    @Autowired
    private JwtService jwtService;
    @Autowired
    private MyUserDetailsService userDetailsService;

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain) throws ServletException, IOException {
        String authHeader = request.getHeader("Authorization");
        String token = null;
        String username = null;

        if (authHeader != null && authHeader.startsWith("Bearer ")) {
            token = authHeader.substring(7);
            username = jwtService.extractUsername(token);
        }

        if (username != null && SecurityContextHolder.getContext().getAuthentication() == null) {
            UserDetails userDetails = userDetailsService.loadUserByUsername(username);
            if (jwtService.validateToken(token, userDetails)) {
                UsernamePasswordAuthenticationToken authToken = new UsernamePasswordAuthenticationToken(userDetails, null, userDetails.getAuthorities());
                authToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }
        filterChain.doFilter(request, response);
    }
}

In SecurityConfig:


@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    return http
        .csrf(csrf -> csrf.disable())
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/login").permitAll()
            .anyRequest().authenticated())
        .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
        .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .build();
}

In JwtService (add):


public String extractUsername(String token) {
    return extractClaim(token, Claims::getSubject);
}

public boolean validateToken(String token, UserDetails userDetails) {
    final String username = extractUsername(token);
    return (username.equals(userDetails.getUsername()) && !isTokenExpired(token));
}

private boolean isTokenExpired(String token) {
    return extractClaim(token, Claims::getExpiration).before(new Date());
}

private <T> T extractClaim(String token, Function<Claims, T> claimsResolver) {
    final Claims claims = extractAllClaims(token);
    return claimsResolver.apply(claims);
}

private Claims extractAllClaims(String token) {
    return Jwts.parser().verifyWith(getKey()).build().parseSignedClaims(token).getPayload();
}

Explanation

- Filter extracts token, validates signature/claims.

- Sets authenticated context if valid.

- Stateless: No sessions.

public class CustomAuthProvider implements AuthenticationProvider {

13. Authorization and Access Control

Concept

- Authorization: What authenticated users can do (post-authentication).

- Access Control: RBAC (roles), ABAC (attributes), ACL (object-level).

- Spring: URL-based, method-level (@PreAuthorize), voter-based.

Example: Role-Based Access Control (RBAC)

- Add roles to User Entity: private String role; (e.g., "ROLE_USER", "ROLE_ADMIN").

- In UserPrincipal: Return new SimpleGrantedAuthority(user.getRole()).

URL-Based (in Config):


authorizeHttpRequests(auth -> auth
    .requestMatchers("/admin/**").hasRole("ADMIN")
    .requestMatchers("/user/**").hasAnyRole("USER", "ADMIN")
    .anyRequest().authenticated());

Method-Level Security:

- Enable: @EnableMethodSecurity on config.

- Example Controller:


@GetMapping("/admin")
@PreAuthorize("hasRole('ADMIN')")
public String adminPage() {
    return "Admin access";
}

@GetMapping("/user")
@PreAuthorize("hasAnyRole('USER', 'ADMIN')")
public String userPage() {
    return "User access";
}

ACL (Advanced Access Control Lists):

- Dependency: spring-security-acl.

- Use for fine-grained permissions (e.g., user owns object).

- Example: AclService to grant/read permissions on entities.

Explanation

- @PreAuthorize: SpEL expressions (e.g., @PreAuthorize("#id == authentication.principal.id") for ownership).

- Why: Prevents unauthorized actions; RBAC is simple, ACL for complex scenarios.
