✅ Step 1: Create a new Spring Boot project

Go to 👉 https://start.spring.io


Project settings:

  • Project: Maven
  • Language: Java
  • Spring Boot: Latest stable version
  • Dependencies:
Spring Web Spring Data JPA MySQL Driver

Click Generate, unzip, and open in your IDE (IntelliJ / VS Code / Eclipse).

✅ Step 2: Add MySQL dependency (if not added)

Check your pom.xml — make sure these are present:

<dependencies>
    <!-- Spring Web -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <!-- JPA for MySQL interaction -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-jpa</artifactId>
    </dependency>

    <!-- MySQL Connector -->
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <scope>runtime</scope>
    </dependency>
</dependencies>
✅ Step 3: Configure MySQL connection

Open src/main/resources/application.properties and add:

spring.application.name=mysqlDemo

# MySQL Database connection
spring.datasource.url=jdbc:mysql://localhost:3306/studentdb
spring.datasource.username=root
spring.datasource.password=yourpassword

# Hibernate settings (auto-create tables)
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.MySQL8Dialect
💡 Make sure:
  • MySQL is installed and running (localhost:3306)
  • Database studentdb exists (CREATE DATABASE studentdb; in MySQL Workbench or terminal)
✅ Step 4: Create an Entity (Model)

📄 Student.java

package com.example.mysqlDemo.model;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

@Entity
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private int age;

    // Constructors
    public Student() {
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Getters & Setters
    public Long getId() {
        return id;
    }
    public void setId(Long id) {
        this.id = id;
    }
    public String getName() {
        return name;
    }
    public void setName(String name) {
        this.name = name;
    }
    public int getAge() {
        return age;
    }
    public void setAge(int age) {
        this.age = age;
    }
}

✅ Step 6: Create Controller

📄 StudentController.java

package com.example.mysqlDemo.controller;

import com.example.mysqlDemo.model.Student;
import com.example.mysqlDemo.repository.StudentRepository;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/students")
public class StudentController {

    private final StudentRepository repository;

    public StudentController(StudentRepository repository) {
        this.repository = repository;
    }

    @PostMapping
    public Student addStudent(@RequestBody Student student) {
        return repository.save(student);
    }

    @GetMapping
    public List<Student> getAllStudents() {
        return repository.findAll();
    }

    @PutMapping("/{id}")
    public Student updateStudent(@PathVariable Long id, 
                                  @RequestBody Student studentDetails) {
        Student student = repository.findById(id).orElseThrow();
        student.setName(studentDetails.getName());
        student.setAge(studentDetails.getAge());
        return repository.save(student);
    }

    @DeleteMapping("/{id}")
    public String deleteStudent(@PathVariable Long id) {
        repository.deleteById(id);
        return "Student deleted successfully";
    }
}

🎯 1. Custom JPA Queries (@Query)

By default, JpaRepository provides basic CRUD methods. But sometimes you need custom queries.


Example: Find students older than a certain age

package com.example.mysqlDemo.repository;

import com.example.mysqlDemo.model.Student;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import java.util.List;

public interface StudentRepository extends JpaRepository<Student, Long> {

    // JPQL query (Java Persistence Query Language)
    @Query("SELECT s FROM Student s WHERE s.age > :age")
    List<Student> findStudentsOlderThan(@Param("age") int age);

    // Derived query method (Spring Data JPA creates query from method name)
    List<Student> findByName(String name);
}
✅ Key Points:
  • @Query allows custom SQL or JPQL queries
  • @Param binds method parameters to the query
  • Spring Data JPA can derive queries from method names automatically

📦 2. DTOs (Data Transfer Objects)

Why use DTOs?

Entities are directly tied to database tables. Sending them directly in APIs is not a good practice. Instead, we use DTOs to send only required data to clients.


Create StudentDTO.java:

package com.example.mysqlDemo.dto;

public class StudentDTO {
    private String name;
    private int age;

    // Constructor
    public StudentDTO(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Getters & Setters
    public String getName() {
        return name;
    }
    public void setName(String name) {
        this.name = name;
    }
    public int getAge() {
        return age;
    }
    public void setAge(int age) {
        this.age = age;
    }
}

Modify controller to return DTOs:

@GetMapping
public List<StudentDTO> getAllStudents() {
    return repository.findAll()
                     .stream()
                     .map(s -> new StudentDTO(s.getName(), s.getAge()))
                     .toList();
}
✅ Benefits:
  • Decouples database structure from API responses
  • Only exposes the necessary data (security)
  • Makes API responses cleaner and more flexible

✔️ 3. Validation (@NotBlank, @Min)

Spring Boot supports Bean Validation to validate incoming request data.


Update Student.java:

import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;

@Entity
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank(message = "Name cannot be blank")
    private String name;

    @Min(value = 0, message = "Age must be positive")
    private int age;

    // ... rest of the code
}

Update controller to validate requests:

import jakarta.validation.Valid;

@PostMapping
public Student addStudent(@Valid @RequestBody Student student) {
    return repository.save(student);
}
✅ Benefits:
  • Prevents invalid data from being saved
  • Provides automatic error messages
  • Reduces manual validation code

🔧 4. Service Layer

Why use a Service layer?

It separates business logic from the controller. Controllers only handle HTTP requests; Services handle the logic.


Create StudentService.java:

package com.example.mysqlDemo.service;

import com.example.mysqlDemo.model.Student;
import com.example.mysqlDemo.repository.StudentRepository;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class StudentService {

    private final StudentRepository repository;

    public StudentService(StudentRepository repository) {
        this.repository = repository;
    }

    public Student addStudent(Student student) {
        return repository.save(student);
    }

    public List<Student> getAllStudents() {
        return repository.findAll();
    }
}

Modify StudentController.java:

@RestController
@RequestMapping("/students")
public class StudentController {

    private final StudentService service;

    public StudentController(StudentService service) {
        this.service = service;
    }

    @PostMapping
    public Student addStudent(@Valid @RequestBody Student student) {
        return service.addStudent(student);
    }

    @GetMapping
    public List<Student> getAllStudents() {
        return service.getAllStudents();
    }
}
✅ Benefits:
  • Makes your code clean, modular, and easy to maintain
  • Controller → Service → Repository → Database (clean flow)
  • Easy to test business logic separately
  • Follows Single Responsibility Principle

🔄 How It Works:

  • Controller → talks to Service
  • Service → talks to Repository
  • Repository → talks to Database
  • DTOs → sent from Service/Controller back to client

📋 Layer Responsibilities:

Layer Responsibility Example
Controller Handle HTTP requests/responses @GetMapping, @PostMapping
Service Business logic & data processing Validation, transformation, calculations
Repository Database operations save(), findAll(), custom queries
Entity Represent database tables @Entity, @Id
DTO Transfer data between layers Send clean API responses

🔍 Request Flow Example:

When a user sends: POST /students with JSON data

  1. 📥 Controller receives the HTTP request
  2. ✔️ Validation checks if data is valid (@Valid)
  3. ⚙️ Service processes business logic
  4. 💾 Repository saves to database via JPA
  5. 🗄️ MySQL stores the student record
  6. 📤 Response goes back through the same layers
  7. 🌐 Client receives the saved student data

🎯 Best Practices:

  • Separation of Concerns: Each layer has a specific responsibility
  • Never skip Service Layer: Always use it for business logic
  • Use DTOs: Don't expose entities directly in APIs
  • Validate early: Use @Valid in controllers
  • Keep controllers thin: Move logic to services
  • Use meaningful names: findStudentsOlderThan() vs findByAge()
