Object Types in TypeScript
Core Concept

In JavaScript, objects are flexible — no strict structure. But in TypeScript, we can define a fixed structure (shape) for objects. This is called an Object Type.

interface Person { name: string; age: number; }
✅ name must be a string  |  ✅ age must be a number  |  ✅ No missing or wrong types allowed

Interface — Blueprint for an Object

interface is used to define object structure. Think of it as a blueprint or rulebook for an object.

interface Person { name: string; age: number; }

Required vs Optional Properties

Required — name: string; and age: number; must be present.

Optional — address?: string; — May or may not exist. No error if missing.

const user: Person = { name: "Alice", age: 30 }; // ✔ Valid — address missing is allowed

Function with Object Type

function greet(person: Person): string { return `Hello, ${person.name}!`; }
Function accepts an object of type Person — ensures the object has correct structure. If you pass a wrong object:
greet({ name: "Bob" }); // ❌ ERROR — age missing

Type Safety — Very Important

ConditionResult
Missing required property❌ Error
Wrong type❌ Error
Extra property (sometimes)⚠️ May warn

Real Example — Car Object

interface Car { make: string; model: string; year: number; electric?: boolean; // optional } const myCar: Car = { make: "Tesla", model: "Model S", year: 2022, electric: true }; const car2: Car = { make: "Toyota", model: "Camry", year: 2020 }; // ✔ Still valid — electric is optional

Nested Object Types — Advanced Concept

Object inside another object — also called composition.
// Step 1: Define inner object interface Author { name: string; birthYear: number; } // Step 2: Use it inside another object interface Book { title: string; author: Author; pages: number; genre?: string; } // Step 3: Create object const myBook: Book = { title: "TypeScript Basics", author: { name: "Jane Doe", birthYear: 1980 }, pages: 350 };

Functions with Object Parameters

interface Rectangle { width: number; height: number; } function calculateArea(rect: Rectangle): number { return rect.width * rect.height; } const myRectangle = { width: 10, height: 5 }; calculateArea(myRectangle); // 50

Why TypeScript Object Types are Important

  • Prevent runtime errors
  • Improve code readability
  • Help in large projects
  • Better auto-complete in editors
  • Easier debugging
⚙
Interfaces — Deep Dive
Contract / Rulebook

An interface is like a contract / rulebook. It tells:

  • What properties an object must have
  • What methods it must implement
  • But NOT how they work (no logic)
interface Car { make: string; model: string; year: number; } // Any object of type Car MUST have these 3 properties

No Implementation Allowed

Interface only defines structure, not behavior.
// ❌ NOT allowed interface Test { value: number; getValue() { return 10; } // ❌ NOT allowed } // ✅ Allowed — only signature interface Test { value: number; getValue(): number; }

Interface with Class — implements

When a class uses implements, it MUST follow the interface rules.
interface Employee { name: string; age: number; position: string; } class Manager implements Employee { name: string; age: number; position: string; constructor(name: string, age: number, position: string) { this.name = name; this.age = age; this.position = position; } } const manager1 = new Manager("John Doe", 35, "Project Manager");
implements means: "This class promises to follow the interface." If position is missing → ❌ ERROR

Interface with Method Signatures

interface Calculator { add(a: number, b: number): number; subtract(a: number, b: number): number; } class SimpleCalculator implements Calculator { add(a: number, b: number): number { return a + b; } subtract(a: number, b: number): number { return a - b; } } const calc = new SimpleCalculator(); calc.add(5, 3); // 8 calc.subtract(9, 4); // 5

Method signature breakdown: add(a: number, b: number): number;

  • Takes 2 numbers
  • Returns a number

❌ Invalid: returning string when signature says number.

Both define custom types in TypeScript, but used in different situations.

Main useAny typeObject structure

Type Alias — Defined with type

type Point = { x: number; y: number; }; function printPoint(point: Point): void { console.log(`x: ${point.x}, y: ${point.y}`); }

Type Alias is very powerful — it can define:

Object Primitive — type ID = number Union — "success" | "error" Tuple — [number, string]

Interfaces cannot do all of this.

Extending — Very Important

// Type Alias → uses & (Intersection) type A = { a: number }; type B = { b: number }; type C = A & B; // Result: { a: number; b: number } // Interface → uses extends interface A { a: number; } interface B extends A { b: number; }
Type → combine using &  |  Interface → extend using extends

Can Both Extend Each Other? — Yes!

// Type extending Interface interface A { a: number; } type B = A & { b: number }; // Interface extending Type type A = { a: number; }; interface B extends A { b: number; }

Classes — implements

// Interface with Class interface Animal { name: string; } class Dog implements Animal { name: string = "Tommy"; } // Type Alias with Class type Animal = { name: string; }; class Dog implements Animal { name: string = "Tommy"; }
✔ Both work with implements — but Interface is preferred.

Declaration Merging — Big Difference

// ❌ Type Alias — NOT allowed type A = { x: number }; type A = { y: number }; // ❌ ERROR — Duplicate identifier // ✅ Interface — ALLOWED (Declaration Merging) interface A { x: number; } interface A { y: number; } // Result: { x: number; y: number }
This is called Declaration Merging — only interfaces support it.

When to Use What — Real-world Rule

Use Interface when
  • Working with objects
  • Using classes (OOP)
  • Need extendability
  • Want cleaner structure
Use Type Alias when
  • Need union (A | B)
  • Need tuple ([x, y])
  • Need complex types
  • Need flexibility
