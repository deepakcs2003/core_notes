A practical example

An Employee clicks the login button.

  1. React takes the email/password from the login form.
  2. The React API service sends the request POST /api/v1/auth/login to NestJS.
  3. NestJS verifies the credentials.
  4. The backend returns a JWT token.
  5. React manages the authenticated user and the token.
  6. The user navigates to the dashboard.
  7. In the following protected API requests, the Bearer token is sent.

4. Technology stack: what does each one do?

  • React (UI library). With React we divide the UI into small reusable components, like Navbar, Sidebar, TicketCard, LoginForm and Dashboard. Official: React Learn
  • TypeScript (type safety). It adds static types on top of JavaScript. It tells whether a variable is a string, a number, an object or some specific structure.
  • Vite (development and build tool). It starts the development server, processes the code and makes the production build. With fast refresh, changes show up quickly in the browser. Official: Vite Guide
  • Tailwind CSS (styling). We design with utility classes, like flex, p-4, bg-white, rounded-lg, text-xl. Official: Tailwind Vite Setup

function Welcome() {

  • return: returns the UI.
  • <h1>: heading.
  • className: assigns a CSS class.
  • text-2xl: text size.
  • font-bold: bold font.
  • text-blue-600: text color.

6. Project folder structure: purpose of every file

When the React project is created, you get a structure like this:

internal-it-helpdesk-frontend/
│
├── public/                 Static files
│
├── src/                    Main source code
│   ├── assets/             Images, icons
│   ├── App.css             Component styling
│   ├── App.tsx             Main UI component
│   ├── index.css           Global CSS
│   └── main.tsx            React entry point
│
├── index.html              Browser HTML entry
├── package.json           Dependencies and scripts
├── tsconfig.json           TypeScript configuration
├── vite.config.ts          Vite configuration
└── node_modules/           Installed packages

Now understand the role of every folder and file.

  1. public/ holds static files that are not processed like normally imported assets in the bundling process. Example: public/logo.svg, public/favicon.ico.
  2. src/ is where we write our actual React code. Almost the whole frontend is developed in this folder.
  3. assets/ is for imported images, SVGs and other assets.
  4. App.tsx is our main application component. Initially we write the application’s UI inside it.
  5. main.tsx is the entry point of the React application. From here React renders the application inside the browser’s HTML element.
  6. index.html is the initial HTML page that the browser receives.
  7. package.json stores the project dependencies, scripts and package metadata.
  8. node_modules/ holds the actual code of the installed npm packages. Do not edit this folder manually.
  9. vite.config.ts is for the development/build configuration of Vite.
Phase 1 · Lesson 3

7. How does a React application run in the browser?

This is a very important diagram. After understanding it, the purpose of main.tsx becomes clear.

React rendering flow

  1. index.htmlHTML page and the root element: <div id="root"></div>
  2. main.tsxStarts the React application
  3. App.tsxMain component and UI
  4. Child ComponentsNavbar · Sidebar · Cards · Tables
  5. Browser UIThe rendered page is shown to the user

Open index.html

You will find something like this:

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Vite + React + TS</title>
  </head>

  <body>
    <div id="root"></div>

    <script
      type="module"
      src="/src/main.tsx"
    ></script>
  </body>
</html>
  • <div id="root"></div> is an empty HTML container. React will render its complete UI inside this container.
  • type="module" tells the browser to load the script as a JavaScript module, in which we can use import and export.
  • src="/src/main.tsx" tells the browser that the starting code of the React application is main.tsx.

Open main.tsx

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

import './index.css';
import App from './App.tsx';

createRoot(
  document.getElementById('root')!
).render(
  <StrictMode>
    <App />
  </StrictMode>
);

Understand it:

  • import { StrictMode } from 'react' imports a development helper of React.
  • import { createRoot } from 'react-dom/client' gives React the entry point to render the application in the browser DOM.
  • import './index.css' loads the global stylesheet.
  • import App from './App.tsx' imports the main App component.
  • document.getElementById('root') finds the element with id="root" in the HTML page.
  • ! is the TypeScript non-null assertion. We tell TypeScript that the root element is available here. If the root element is missing in the HTML, a runtime error can come.
  • .render() renders the React component in the root element.
  • <StrictMode> helps identify potential problems in development. Because of some development checks, effects can appear to run twice. This behavior is not the same in production.
Phase 1 · Lesson 4

8. Install and configure Tailwind CSS

Now we install Tailwind CSS for styling. The current Vite setup of Tailwind CSS uses the @tailwindcss/vite plugin. We follow the latest official Vite integration. In the terminal:

npm install tailwindcss @tailwindcss/vite

Step 8.1: update vite.config.ts

The default React template will have code like this:

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
});

Update it:

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  plugins: [
    react(),
    tailwindcss(),
  ],
});
  • defineConfig(): a helper to define the Vite configuration.
  • react(): gives Vite React support.
  • tailwindcss(): integrates Tailwind CSS with Vite.
  • plugins: to add additional functionality in Vite.

Step 8.2: update src/index.css

Remove the old CSS and write:

@import "tailwindcss";

* {
  box-sizing: border-box;
}

body {
  margin: 0;
  min-width: 320px;
  min-height: 100vh;
  font-family: Arial, Helvetica, sans-serif;
}
  • @import "tailwindcss" loads the utility classes of Tailwind.
  • box-sizing: border-box includes padding and border in the element’s width calculation. It makes the layout easy to manage.
  • margin: 0 removes the browser’s default body margin.
  • min-height: 100vh gives the body a minimum viewport height.

Open src/App.tsx and replace the existing code:

Important concepts of the code

1. Component function

function App() {
  return (...);
}

A React component is a JavaScript/TypeScript function that returns JSX. The name of a React component must start with a capital letter. Like App, Navbar, TicketCard.

2. JSX

<h1>Dashboard</h1>

JSX lets us write HTML-like markup syntax inside JavaScript. There are some differences in React JSX:

  • className instead of class.
  • Tags must be properly closed.
  • A component must return one parent element or a Fragment.

3. Nested elements

<div>
  <h1>Dashboard</h1>
  <p>Welcome</p>
</div>

Putting other elements inside an element is called nesting.

4. Responsive grid

<div className="grid grid-cols-1 gap-5 sm:grid-cols-2 lg:grid-cols-4">
  • Normal small screen: 1 column.
  • From the sm breakpoint: 2 columns.
  • From the lg breakpoint: 4 columns.

This is the basic concept of responsive design.

5. JSX comments

{/* Top Navbar */}

This is the syntax to write a comment inside JSX.

10. Environment variables and package.json

Environment variables: configure the backend URL

We have not connected the frontend and the backend yet. But let us prepare the base URL for the connection. Create a .env file in the project root:

VITE_API_BASE_URL=http://localhost:3000/api/v1

Why the VITE_ prefix? By default Vite uses the VITE_ prefix to expose environment variables in the frontend.

const apiUrl = import.meta.env.VITE_API_BASE_URL;

console.log(apiUrl);

Output:

http://localhost:3000/api/v1
Security warning: environment variables in the frontend are not private secrets. VITE_ variables can be visible in the browser bundle. So never keep a JWT secret, a database password or private API keys here.

If you create/update the .env file, restart the Vite dev server. For the backend we use the same base prefix we configured in NestJS: /api/v1.

File: package.json. It will have roughly this structure:

Difference between development and production

Development mode (while coding): npm run dev

  • Fast development server.
  • The browser refreshes/updates on code changes.
  • Debugging is easy.

Production mode (when the project is ready): npm run build

  • Optimized output is generated.
  • The dist/ folder is created.
  • You get assets ready for deployment.

Vite provides separate commands for the development server and the production build.

Introduction to React

React is a JavaScript library used to build user interfaces (UI). In simple language: suppose we are building our Internal IT Helpdesk Management System. This application will have multiple screens:

  • Login Page
  • Register Page
  • Admin Dashboard
  • Employee Dashboard
  • Ticket List
  • Ticket Details
  • Create Ticket Form
  • User Management
  • Audit Logs

We will build the frontend of all these screens with React. The main job of React is to divide the UI into small, manageable and reusable parts.

Without React and with React

Suppose this is a normal HTML website:

<!DOCTYPE html>
<html>
<head>
    <title>Helpdesk</title>
</head>
<body>

    <h1>IT Helpdesk</h1>

    <button>Login</button>

</html>

Here HTML tells the browser what to display on the page. But when the application becomes complex, updating and managing multiple UI elements can become difficult.

In React we divide the UI into components. Example:

App

│
├── Sidebar
│

│   ├── StatCard
│   ├── StatCard

Every component has its own specific responsibility. For example:

  • Navbar: displays the top navigation.
  • Sidebar: displays the application navigation.
  • StatCard: displays the ticket statistics.
  • RecentTickets: displays the recent tickets.

This makes the code manageable and reusable.

Phase 2 · Lesson 2.4

13. What is a React Component?

The component is the most important fundamental concept of React. A component is a reusable piece of UI.

Example: our Helpdesk dashboard has 4 statistics cards. If we write separate HTML for every card, the code will repeat. In React we can make one component:

function StatCard() {
  return (
    <div className="rounded-xl bg-white p-6 shadow">
      <p>Total Tickets</p>
      <h2>250</h2>
    </div>
  );
}

export default StatCard;

Now we can use this component multiple times:

function App() {
  return (
    <div>
      <StatCard />
      <StatCard />
      <StatCard />
      <StatCard />
    </div>
  );
}

export default App;
Right now all the cards will show the same data. In the Props lesson we will learn how to pass different data to the same component.

Internal structure of a React component

Understand the 3 important parts of a typical React component:

  1. Function DeclarationThe name of the component and the function body
  2. JSX ReturnDefines the structure of the UI
  3. ExportLets the component be used in other files
function Navbar() {

  // Component logic

  return (
    <nav>
      <h1>IT Helpdesk</h1>
    </nav>
  );
}

export default Navbar;
  1. function Navbar(): it is a JavaScript function. The name of the React component is Navbar. React component names must start with a capital letter.
  2. return (...): returns the UI of the component. We write JSX inside it.
  3. export default Navbar: gives the permission to import the component in other files.

This is a very important concept of React.

What is JSX?

The full form of JSX is JavaScript XML. JSX is a syntax extension that lets us write an HTML-like structure inside JavaScript.

Normal JavaScript:

const heading = "IT Helpdesk";

React JSX:

const heading = <h1>IT Helpdesk</h1>;

Here <h1> looks like HTML, but it is JSX syntax.

Why do we use JSX?

Suppose we want to display a heading, a paragraph and a button. Creating the UI without JSX is comparatively difficult and verbose. With JSX:

function App() {
  return (
    <div>
      <h1>IT Helpdesk</h1>
      <p>Manage your support tickets.</p>
      <button>Login</button>
    </div>
  );
}

Important rules of JSX

Rule 1: you must return one parent element.

Incorrect:

function App() {
  return (
    <h1>Hello</h1>
    <p>Welcome</p>
  );
}

Correct:

function App() {
  return (
    <div>
      <h1>Hello</h1>
      <p>Welcome</p>
    </div>
  );
}

Rule 2: in JSX we use className instead of class.

<div className="bg-blue-500">
  Helpdesk
</div>

Rule 3: self-closing tags must be closed.

<img src="/logo.png" alt="Logo" />

<input type="text" />

<br />

Rule 4: we write JavaScript expressions inside {}.

function App() {

  const username = "Admin";

  return (
    <div>
      <h1>Welcome {username}</h1>
    </div>
  );
}

Browser output: Welcome Admin

JavaScript expressions in JSX

function App() {

  const totalTickets = 250;

  const username = "Admin";

  return (
    <div>
      <h1>{username}</h1>

      <p>Total Tickets: {totalTickets}</p>

      <p>Next value: {totalTickets + 10}</p>
    </div>
  );
}

We can write JavaScript expressions inside the curly braces {}.

18. Props kya hote hain?

Aaj hum React ka ek bahut important concept seekhenge: Props (Properties). Is concept ko achhe se samajhna zaroori hai, kyunki hamare IT Helpdesk project mein same component ko different data ke saath baar-baar use karna hoga.

Props ka use parent component se child component ko data pass karne ke liye hota hai.

Simple example: Suppose hamare dashboard par 4 cards hain:

Total TicketsOpen TicketsIn ProgressResolved
2506545110

In sabhi cards ka design almost same hai. Sirf title, number aur color different hain. Agar hum 4 alag components banayenge, toh code repeat hoga. Instead, hum ek hi component banayenge aur usko different data pass karenge. Isi data ko Props kehte hain.

Without Props vs With Props

Without Props

function TotalTickets() {
  return (
    <div>
      <h3>Total Tickets</h3>
      <p>250</p>
    </div>
  );
}

function OpenTickets() {
  return (
    <div>
      <h3>Open Tickets</h3>
      <p>65</p>
    </div>
  );
}

function ResolvedTickets() {
  return (
    <div>
      <h3>Resolved Tickets</h3>
      <p>110</p>
    </div>
  );
}

Problem: Har card ke liye separate component banana pad raha hai.

With Props

function StatCard(props) {
  return (
    <div>
      <h3>{props.title}</h3>
      <p>{props.value}</p>
    </div>
  );
}

Ab same component multiple times use kar sakte hain:

function Dashboard() {
  return (

      <StatCard title="Open Tickets" value={65} />

Yahan:

  • StatCard child component hai.
  • Dashboard parent component hai.
  • title aur value props hain.

Parent aur Child Component ka relationship

Is relationship ko visualize karo: Parent → Child Data Flow

  1. Dashboard (Parent)Data provide karta hai: <StatCard title="Total Tickets" value={250} />
  2. Props pass hote hain
  3. StatCard (Child)Props receive karta hai: props.title, props.value
  4. Rendered UITotal Tickets: 250
Important: React mein props ka normal data flow parent se child ki taraf hota hai.

19. Props with TypeScript aur Destructuring

Abhi tak humne simple JavaScript-style props dekhe. Lekin hamara project TypeScript mein hai. TypeScript mein humein props ka data type define karna chahiye.

interface StatCardProps {
  title: string;
  value: number;
}

function StatCard(props: StatCardProps) {
  return (
    <div>
      <h3>{props.title}</h3>
      <p>{props.value}</p>
    </div>
  );
}

export default StatCard;

Line-by-line explanation

Step 1: Interface

interface StatCardProps {
  title: string;
  value: number;
}

interface TypeScript ka feature hai. Ye define karta hai ki component ko kis structure ka data receive karna hai.

  • title: string: title text hona chahiye.
  • value: number: value number honi chahiye.

Step 2: Function parameter

function StatCard(props: StatCardProps)

Iska meaning hai ki StatCard component ko StatCardProps ke according data milega.

Step 3: Accessing props

<h3>{props.title}</h3>
<p>{props.value}</p>

props.title se title access karenge. props.value se number access karenge.

TypeScript ka benefit

Agar hum galat data pass karte hain:

<StatCard title="Total Tickets" value="250" />

TypeScript error dega, kyunki value ka type number hona chahiye, string nahi. Correct:

<StatCard title="Total Tickets" value={250} />

Dhyan do: JSX mein string ko quotes mein aur JavaScript values ko curly braces mein likhte hain.

Destructuring Props

React code mein tumhe ye pattern bahut baar dikhega:

function StatCard({ title, value }: StatCardProps) {
  return (
    <div>
      <h3>{title}</h3>
      <p>{value}</p>
    </div>
  );
}

Isko Object Destructuring kehte hain.

Without destructuring:

function StatCard(props: StatCardProps) {
  return <h3>{props.title}</h3>;
}

With destructuring:

function StatCard({ title }: StatCardProps) {
  return <h3>{title}</h3>;
}

Dono ka output same hai. Destructuring se code shorter aur readable ho jaata hai.

Kabhi-kabhi component ko kuch props dena optional rakhna hota hai. TypeScript mein ? use karte hain.

interface UserProps {
  name: string;
  role?: string;
}

Yahan name required hai aur role optional hai. Example:

function UserInfo({ name, role }: UserProps) {
  return (
    <div>

Agar parent component koi optional prop pass nahi karta, toh hum default value de sakte hain.

interface UserProps {

function UserInfo({

Reusable component kya hai?

Reusable component ek aisa component hai jise application mein multiple places par use kiya ja sakta hai. Example:

  • Button

  • Card
  • Modal
  • Loader
  • Badge

Hamare project mein ek common button ko Login, Create Ticket, Update Ticket aur Save ke liye use kar sakte hain.

Reusable Button component banate hain

src/components/common/Button.tsx

import type { ReactNode, ButtonHTMLAttributes } from "react";

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  children: ReactNode;
  variant?: "primary" | "secondary" | "danger";
}

function Button({
  children,
  variant = "primary",
  className = "",
  ...props
}: ButtonProps) {

  const baseStyles =
    "rounded-lg px-5 py-2.5 font-medium transition-colors";

  const variantStyles = {
    primary: "bg-blue-600 text-white hover:bg-blue-700",
    secondary: "bg-slate-200 text-slate-800 hover:bg-slate-300",
    danger: "bg-red-600 text-white hover:bg-red-700",
  };

  return (
    <button
      className={`${baseStyles} ${variantStyles[variant]} ${className}`}
      {...props}
    >
      {children}
    </button>
  );
}

export default Button;

Ab isko detail mein samjho.

A. ButtonHTMLAttributes

ButtonHTMLAttributes<HTMLButtonElement>

React ka built-in TypeScript type hai. Isse normal HTML button ke standard props ka support milta hai, jaise onClick, disabled, type, id, title. Isliye humein har button attribute separately define nahi karna padta.

B. Interface extends

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement>

extends ka matlab existing type ki properties inherit karke apni additional properties add karna. Yahan hum normal HTML button attributes ke saath variant bhi add kar rahe hain.

C. Union Type

variant?: "primary" | "secondary" | "danger";

Iska matlab variant mein sirf in teen values mein se koi ek allowed hai.

D. Default parameter

variant = "primary"

Agar parent variant pass nahi karta, toh primary button show hoga.

E. Rest operator

...props

Baaki received button properties ko collect karta hai.

F. Spread operator

{...props}

Collected properties ko actual HTML button element tak forward karta hai.

25. React Lists aur Keys

Ab hum seekhenge ki multiple data items ko dynamically UI mein kaise display karte hain. Helpdesk application mein tickets ki list hoti hai. Har ticket ko manually JSX mein likhna practical nahi hoga.

1. Static approach

<div>
  <p>Ticket 1 - Laptop Issue</p>
  <p>Ticket 2 - Network Issue</p>
  <p>Ticket 3 - Software Issue</p>
</div>

Problem: Agar 1000 tickets hain, toh 1000 elements manually likhna possible nahi hai.

2. Dynamic approach using map()

JavaScript ka map() array method har item ko transform karke ek naya array return karta hai. Example:

const tickets = [
  { id: 1, title: "Laptop Issue" },
  { id: 2, title: "Network Issue" },
  { id: 3, title: "Software Issue" },
];

Ab:

function TicketList() {
  return (
    <div>
      {tickets.map((ticket) => (
        <p key={ticket.id}>
          {ticket.title}
        </p>
      ))}
    </div>
  );
}

Explanation:

  • tickets: array hai.
  • .map(): array ke har item par callback execute karta hai.
  • ticket: current array item hai.
  • ticket.title: current ticket ka title.
  • key: React ko har list item ki stable identity provide karti hai.

3. Key prop kya hota hai?

React ko list mein identify karna hota hai ki kaunsa item add, remove ya update hua. Iske liye hum key provide karte hain.

Correct:

{tickets.map((ticket) => (
  <p key={ticket.id}>
    {ticket.title}
  </p>
))}

Avoid:

{tickets.map((ticket, index) => (
  <p key={index}>
    {ticket.title}
  </p>
))}

Jab list reorder ya items insert/delete ho sakte hain, tab index unstable identity ban sakta hai. Isliye database se milne wali unique ticket ID generally better hai.

26. React Fragments

Kabhi-kabhi humein multiple elements return karne hote hain, lekin extra div nahi chahiye. Is situation mein React Fragment use hota hai.

Without Fragment:

function App() {
  return (
    <div>
      <h1>Helpdesk</h1>
      <p>Welcome Admin</p>
    </div>
  );
}

With Fragment:

function App() {
  return (
    <>
      <h1>Helpdesk</h1>
      <p>Welcome Admin</p>
    </>
  );
}

<>...</> short syntax hai React Fragment ka. Full syntax:

import { Fragment } from "react";

function App() {
  return (
    <Fragment>
      <h1>Helpdesk</h1>
      <p>Welcome Admin</p>
    </Fragment>
  );
}

Benefit: Extra DOM element create nahi hota.

27. React Rendering: Complete Understanding

Ab tak humne React components create karna, props dena, composition, lists aur reusable components samjhe. Ab complete rendering flow samajhte hain.

1. React application ka flow

  1. index.htmlContains root DOM element
  2. main.tsxMounts the React application
  3. App.tsxRoot component
  4. Component TreeNavbar, Sidebar, Dashboard, StatCard, TicketList
  5. React DOMUpdates the browser DOM

2. Render vs Re-render

Render: React component ko execute karke uska UI output calculate karta hai.

Re-render: Jab component ki relevant state, props ya context change hoti hai, React component ko dobara render kar sakta hai.

Example:

function Welcome() {
  console.log("Component rendered");

  return <h1>Welcome to Helpdesk</h1>;
}

Jab React Welcome component render karega, console mein message show hoga. Abhi component ke andar state nahi hai, lekin future mein useState aur events use karne par re-render ka behavior detail mein samjhenge.

Important concepts:

  • Render ka matlab necessarily poora browser page reload hona nahi hai.
  • React UI changes ko efficiently update karta hai.
  • Props aur state changes rendering ko trigger kar sakte hain.
  • React reconciliation process ke through previous aur next UI output ko compare karke required DOM changes commit karta hai.
