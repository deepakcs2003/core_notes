🧠 1. Process Management

💡 Concept

In Java, we can simulate process creation by starting external programs using Runtime.exec() or ProcessBuilder.

✅Example: Launching a Process

public class ProcessDemo {
    public static void main(String[] args) {
        try {
            // Runtime.getRuntime().exec() → creates a new process
            // Open Notepad (Windows) or another app
            // You can replace "notepad" with "calc" or any command
            // Linux: "gedit", "ls"
            Process process = Runtime.getRuntime().exec("notepad");
            
            // The Process object gives control (wait, exit value, etc.)
            System.out.println("Process started: " + process);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

🧩 Explanation:

  • Runtime.getRuntime().exec() → creates a new process.
  • You can replace "notepad" with "calc" or any command (Linux: "gedit", "ls").
  • The Process object gives control (wait, exit value, etc.).

🔄 2. Threading and Synchronization

💡 Concept

Two threads (Odd & Even) share one variable. Synchronization ensures no interleaving errors.

✅Code: Odd–Even Number Printing

class NumberPrinter {
    private int number = 1;
    private final int MAX = 10;

    // synchronized ensures only one thread can execute this method at a time
    public synchronized void printOdd() {
        while (number < MAX) {
            // If number is even, wait() releases the lock temporarily
            while (number % 2 == 0) {
                try { wait(); } catch (InterruptedException e) {}
            }
            // Print odd number and increment
            System.out.println("Odd: " + number++);
            
            // notify() wakes up the waiting even thread
            notify();
        }
    }

    public synchronized void printEven() {
        while (number <= MAX) {
            // If number is odd, wait for odd thread to finish
            while (number % 2 != 0) {
                try { wait(); } catch (InterruptedException e) {}
            }
            // Print even number and increment
            System.out.println("Even: " + number++);
            
            // notify() wakes up the waiting odd thread
            notify();
        }
    }
}

public class OddEvenThreads {
    public static void main(String[] args) {
        // Shared object between threads
        NumberPrinter printer = new NumberPrinter();
        
        // Create two threads using method references
        Thread t1 = new Thread(printer::printOdd);
        Thread t2 = new Thread(printer::printEven);
        
        // Start both threads - they will alternate properly
        t1.start();
        t2.start();
    }
}

🧩 Explanation:

  • wait() releases the lock temporarily.
  • notify() wakes the waiting thread.
  • Ensures Odd and Even threads alternate properly.

🧵 3. Producer–Consumer Problem

💡 Concept

Producer adds items into a shared buffer; Consumer removes them. Must avoid overflow (buffer full) and underflow (buffer empty).

✅Code

import java.util.LinkedList;
import java.util.Queue;

class SharedBuffer {
    // Queue acts as the shared buffer between producer and consumer
    private final Queue<Integer> buffer = new LinkedList<>();
    private final int CAPACITY = 5;

    // Producer adds items to buffer
    public synchronized void produce(int value) throws InterruptedException {
        // If buffer is full, wait for consumer to consume
        while (buffer.size() == CAPACITY) {
            wait(); // wait for consumer
        }
        // Add item to buffer
        buffer.add(value);
        System.out.println("Produced: " + value);
        
        // notifyAll() wakes up consumer threads
        notifyAll(); // notify consumer
    }

    // Consumer removes items from buffer
    public synchronized void consume() throws InterruptedException {
        // If buffer is empty, wait for producer to produce
        while (buffer.isEmpty()) {
            wait(); // wait for producer
        }
        // Remove item from buffer
        int value = buffer.poll();
        System.out.println("Consumed: " + value);
        
        // notifyAll() wakes up producer threads
        notifyAll(); // notify producer
    }
}

public class ProducerConsumer {
    public static void main(String[] args) {
        // Create shared buffer object
        SharedBuffer buffer = new SharedBuffer();

        // Producer thread - produces 10 items
        Thread producer = new Thread(() -> {
            for (int i = 1; i <= 10; i++) {
                try {
                    buffer.produce(i);
                    // Sleep to simulate production time
                    Thread.sleep(200);
                } catch (InterruptedException e) {}
            }
        });

        // Consumer thread - consumes 10 items
        Thread consumer = new Thread(() -> {
            for (int i = 1; i <= 10; i++) {
                try {
                    buffer.consume();
                    // Sleep to simulate consumption time (slower than producer)
                    Thread.sleep(300);
                } catch (InterruptedException e) {}
            }
        });

        // Start both threads
        producer.start();
        consumer.start();
    }
}

🧩 Explanation:

  • Uses wait() and notifyAll() to coordinate.
  • Prevents producer from adding when buffer is full.

🔒 4. Deadlock Example

💡 Concept

Two threads hold different resources and wait for each other → deadlock.

✅Code

public class DeadlockExample {
    public static void main(String[] args) {
        // Two resources that threads will compete for
        String pen = "Pen";
        String paper = "Paper";

        // Thread 1: locks Pen first, then tries to lock Paper
        Thread t1 = new Thread(() -> {
            synchronized (pen) {
                System.out.println("Thread 1 locked Pen");
                try { Thread.sleep(100); } catch (InterruptedException e) {}
                
                // Now trying to lock Paper - but Thread 2 has it!
                synchronized (paper) {
                    System.out.println("Thread 1 locked Paper");
                }
            }
        });

        // Thread 2: locks Paper first, then tries to lock Pen
        Thread t2 = new Thread(() -> {
            synchronized (paper) {
                System.out.println("Thread 2 locked Paper");
                try { Thread.sleep(100); } catch (InterruptedException e) {}
                
                // Now trying to lock Pen - but Thread 1 has it!
                // Both threads wait forever → DEADLOCK!
                synchronized (pen) {
                    System.out.println("Thread 2 locked Pen");
                }
            }
        });

        // Start both threads - they will deadlock
        t1.start();
        t2.start();
    }
}

🧩 Explanation:

  • Thread 1: locks Pen, waits for Paper.
  • Thread 2: locks Paper, waits for Pen.
  • → Both wait forever → deadlock.

🍽️ 5. Dining Philosophers Problem

💡 Concept

Five philosophers share five chopsticks; each must pick two to eat. Goal: prevent deadlock.

✅Code

import java.util.concurrent.locks.ReentrantLock;

class Philosopher implements Runnable {
    // Each philosopher needs two chopsticks (left and right)
    private final ReentrantLock leftChopstick;
    private final ReentrantLock rightChopstick;
    private final int id;

    public Philosopher(int id, ReentrantLock left, ReentrantLock right) {
        this.id = id;
        this.leftChopstick = left;
        this.rightChopstick = right;
    }

    public void run() {
        try {
            // Infinite loop: philosopher alternates between thinking and eating
            while (true) {
                think();
                eat();
            }
        } catch (InterruptedException e) {}
    }

    // Philosopher is thinking (not using chopsticks)
    private void think() throws InterruptedException {
        System.out.println("Philosopher " + id + " is thinking");
        Thread.sleep(500);
    }

    // Philosopher picks up both chopsticks, eats, then puts them down
    private void eat() throws InterruptedException {
        // Lock both chopsticks (ReentrantLock avoids busy waiting)
        leftChopstick.lock();
        rightChopstick.lock();
        
        // Now eating with both chopsticks
        System.out.println("Philosopher " + id + " is eating");
        Thread.sleep(500);
        
        // Release both chopsticks after eating
        leftChopstick.unlock();
        rightChopstick.unlock();
    }
}

public class DiningPhilosophers {
    public static void main(String[] args) {
        // Create 5 chopsticks (one between each pair of philosophers)
        ReentrantLock[] chopsticks = new ReentrantLock[5];
        for (int i = 0; i < 5; i++)
            chopsticks[i] = new ReentrantLock();

        // Create 5 philosophers, each with left and right chopstick
        // Philosopher i has chopstick i (left) and (i+1)%5 (right)
        for (int i = 0; i < 5; i++) {
            Philosopher p = new Philosopher(i, chopsticks[i], chopsticks[(i + 1) % 5]);
            new Thread(p).start();
        }
        
        // Note: This can still deadlock. Solution: odd-even reversal trick
        // or use tryLock() with timeout
    }
}

🧩 Explanation:

  • Each philosopher tries to lock two chopsticks.
  • ReentrantLock avoids busy waiting.
  • Can use odd-even reversal trick to avoid deadlock.

📖 6. Reader–Writer Problem

💡 Concept

Multiple readers can read simultaneously. Only one writer can write, and no readers during writing.

✅Code

class ReadWrite {
    // Counter to track how many readers are currently reading
    private int readers = 0;

    // Reader starts reading - multiple readers can read simultaneously
    public synchronized void startRead() throws InterruptedException {
        readers++;
        System.out.println("Reader started. Readers: " + readers);
    }

    // Reader finishes reading
    public synchronized void endRead() {
        readers--;
        System.out.println("Reader ended. Readers: " + readers);
        // Notify waiting writer that a reader has finished
        notifyAll();
    }

    // Writer wants to write - must wait until no readers are active
    public synchronized void startWrite() throws InterruptedException {
        // Wait until all readers finish (readers > 0 means someone is reading)
        while (readers > 0) wait();
        System.out.println("Writer started writing...");
    }

    // Writer finishes writing
    public synchronized void endWrite() {
        System.out.println("Writer ended writing.");
        // Notify all waiting readers/writers
        notifyAll();
    }
}

public class ReaderWriter {
    public static void main(String[] args) {
        // Shared ReadWrite object
        ReadWrite rw = new ReadWrite();

        // Reader task
        Runnable reader = () -> {
            try {
                rw.startRead();
                // Simulate reading time
                Thread.sleep(500);
                rw.endRead();
            } catch (InterruptedException e) {}
        };

        // Writer task
        Runnable writer = () -> {
            try {
                rw.startWrite();
                // Simulate writing time
                Thread.sleep(500);
                rw.endWrite();
            } catch (InterruptedException e) {}
        };

        // Create 3 reader threads - they can all read simultaneously
        for (int i = 0; i < 3; i++) new Thread(reader).start();
        
        // Create 1 writer thread - it must wait for all readers to finish
        new Thread(writer).start();
    }
}

🧩 Explanation:

  • readers count tracks active readers.
  • Writer waits until no readers are active.

⚙️ 7. CPU Scheduling Simulation

✅FCFS (First Come First Serve)

import java.util.Scanner;

public class FCFS {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter number of processes: ");
        int n = sc.nextInt();

        // bt = Burst Time, wt = Waiting Time, tat = Turn Around Time
        int[] bt = new int[n], wt = new int[n], tat = new int[n];

        // Input burst times for each process
        System.out.println("Enter burst times:");
        for (int i = 0; i < n; i++) bt[i] = sc.nextInt();

        // Calculate waiting time for each process
        // First process has 0 waiting time
        wt[0] = 0;
        // Waiting time = previous waiting time + previous burst time
        for (int i = 1; i < n; i++)
            wt[i] = wt[i - 1] + bt[i - 1];

        // Calculate turnaround time for each process
        // Turnaround time = Waiting time + Burst time
        for (int i = 0; i < n; i++)
            tat[i] = wt[i] + bt[i];

        // Display results in tabular format
        System.out.println("P\tBT\tWT\tTAT");
        for (int i = 0; i < n; i++)
            System.out.println((i + 1) + "\t" + bt[i] + "\t" + wt[i] + "\t" + tat[i]);
    }
}

🧠 8. LRU Cache Implementation

💡 Concept

LRU Cache removes the least recently used item when the cache is full. To achieve O(1) operations for get() and put(), we use HashMap to store key-node pairs and Doubly Linked List to maintain access order.

Operation Description Time Complexity
get(key) Return value if key exists; else return -1 O(1)
put(key, value) Insert or update; if full, remove least recently used O(1)
moveToHead(node) When accessed, move node to head O(1)
removeTail() Remove least recently used (tail) node O(1)

✅LRU Cache Code

import java.util.*;

class LRUCache {
    // Node for doubly linked list
    class Node {
        int key, value;
        Node prev, next;

        Node(int key, int value) {
            this.key = key;
            this.value = value;
        }
    }

    private final int capacity;
    private Map<Integer, Node> cache;
    private Node head, tail; // dummy nodes for easy operations

    public LRUCache(int capacity) {
        this.capacity = capacity;
        cache = new HashMap<>();
        head = new Node(0, 0);
        tail = new Node(0, 0);
        head.next = tail;
        tail.prev = head;
    }

    // Get value by key
    public int get(int key) {
        if (!cache.containsKey(key)) {
            return -1;
        }
        Node node = cache.get(key);
        moveToHead(node);
        return node.value;
    }

    // Put new key-value pair
    public void put(int key, int value) {
        if (cache.containsKey(key)) {
            Node node = cache.get(key);
            node.value = value;
            moveToHead(node);
        } else {
            Node newNode = new Node(key, value);
            cache.put(key, newNode);
            addToHead(newNode);

            if (cache.size() > capacity) {
                Node tailNode = removeTail();
                cache.remove(tailNode.key);
            }
        }
    }

    // Add node right after head
    private void addToHead(Node node) {
        node.prev = head;
        node.next = head.next;
        head.next.prev = node;
        head.next = node;
    }

    // Remove a node from its position
    private void removeNode(Node node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    // Move existing node to head
    private void moveToHead(Node node) {
        removeNode(node);
        addToHead(node);
    }

    // Remove the least recently used node
    private Node removeTail() {
        Node res = tail.prev;
        removeNode(res);
        return res;
    }

    // For debugging
    public void printCache() {
        Node cur = head.next;
        System.out.print("Cache: ");
        while (cur != tail) {
            System.out.print("[" + cur.key + "=" + cur.value + "] ");
            cur = cur.next;
        }
        System.out.println();
    }

    // Main to test
    public static void main(String[] args) {
        LRUCache lru = new LRUCache(3);
        lru.put(1, 10);
        lru.put(2, 20);
        lru.put(3, 30);
        lru.printCache();  // [3=30] [2=20] [1=10]
        lru.get(1);
        lru.printCache();  // [1=10] [3=30] [2=20]
        lru.put(4, 40);    // removes least recently used (key 2)
        lru.printCache();  // [4=40] [1=10] [3=30]
    }
}

🧩 Explanation:

  • Node class → stores key, value, and pointers (prev, next).
  • HashMap → gives O(1) lookup by key.
  • addToHead() → insert a node right after dummy head.
  • removeNode() → unlink a node from the list.
  • moveToHead() → when accessed, move node to front.
  • removeTail() → removes least recently used (the node before tail).
  • put() → inserts or updates key-value, evicts least used if capacity exceeded.
  • get() → returns value and updates position to most recent.
